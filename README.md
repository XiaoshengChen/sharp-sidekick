# Sharp Sidekick

一个少说话的捧哏 skill：检查社交内容里的事实错漏和推理缺口，查证后给出一句值得读的回复。

**准确先于幽默，信息增量先于回复数量。没有值得回复的内容，就不回复。**

适用于支持 `SKILL.md` 的 agent 环境。以中文冷面短回复为默认方向，也可跟随目标内容的语言。它是一套可复用的工作流程，不是独立运行的机器人、爬虫或社交平台 SDK。

## 效果示意

以下均为虚构例子：

| 原文 | 回复 |
| --- | --- |
| 转化率从 4% 到 5%，只提升了 1%。 | 增加了 1 个百分点，相对提升是 25%。 |
| 只要售后工单变少，就说明产品变好了。 | 把客服入口藏起来，也能做到。 |
| 这家咖啡馆没开夜场，估计晚上客人太少。 | 没有新证据，不回复。 |

这里的“锋利”是找到真正影响结论的前提。只补一句“还有别的可能”，通常不值得占据评论区。

## 能做什么

- 区分事实断言、猜测、提问、偏好和玩笑，读取原帖及后续补充。
- 查证数字、单位、时间、概念与遗漏条件，优先使用原始资料。
- 用具体反例检查推论，也能用新证据更新旧判断。
- 生成带原文、拟回复、来源和边界的 Markdown 审阅稿。
- 在用户明确授权的账号和范围内发布，并记录结果、防止重复发送。
- 配合宿主的周期任务复查近期内容；允许整轮零回复。

不承诺每条都能逗笑，不为了完成配额制造异议，也不把不同价值偏好判成事实错误。

## 安装

仓库中的 skill 目录为 `skills/sharp-sidekick/`，包含入口、必要参考资料和 Codex 界面元数据。

在 Codex 中，可让内置 skill installer 从本仓库安装 `skills/sharp-sidekick`。也可将整个目录复制到宿主支持的 skills 目录。按[官方本地 skill 文档](https://learn.chatgpt.com/docs/build-skills)，Codex 可使用项目内的 `.agents/skills/` 或用户目录下的 `~/.agents/skills/`。

在仓库根目录手动安装到用户范围：

```sh
mkdir -p "$HOME/.agents/skills"
cp -R skills/sharp-sidekick "$HOME/.agents/skills/"
```

已有同名目录时先检查差异，避免无意覆盖自己的修改。安装后调用 `$sharp-sidekick`；若未出现，重启宿主。其他兼容环境请使用其自己的 skill 安装方式。

## 前置条件

宿主需要具备：

1. 能读取目标社交内容的连接器，或可交互的浏览器；登录由用户完成。
2. 能检索并打开外部资料的研究工具。
3. 能写入本地 Markdown 和私有状态记录的文件能力。
4. 若需要自动运行，由宿主提供调度能力和运行时可用的工具权限。

不需要额外数据库、向量库、抓取服务或自建后台。本仓库不提供 Cookie、账号配置、API 密钥或平台接口的逆向实现。

## 使用

### 先看草稿

```text
使用 $sharp-sidekick。
检查我指定的目标主页最近 30 天的内容，最多选 3 条。
只输出 Markdown 审阅稿，不发布。
每条保留原文链接、拟回复、依据和判断边界。
```

初次使用建议先校准：哪些事实值得纠正、什么反例真正击中前提、哪些回复应删掉。将反馈保存在自己的私有配置中；不要把某一条用户偏好改成对所有用户适用的硬规则。

### 已授权发布

```text
使用 $sharp-sidekick。
按我提供的私有配置，用指定回复账号处理指定目标账号的帖子。
本轮已授权直接发布最多 3 条高质量回复，允许 0 条。
发送前核对账号、原帖上下文和去重记录；发送后逐条验证。
不确定是否发送成功时先核对，不要重发。
```

发布权限来自用户的具体任务，而不是安装这个 skill。平台、工具或宿主要求的验证仍然适用。

### 周期任务

可向支持调度的宿主描述：

```text
每周六上午 10 点，按我指定的时区运行 $sharp-sidekick。
读取私有配置中的目标账号，在实际运行时刻前 7 天发布的内容。
已授权用配置中的回复账号，直接发布 0–3 条符合标准的回复。
没有值得回复的内容就不回复，也不通知。
发布成功、执行失败或需要我处理登录问题时再通知。
私有保存来源、取舍理由、发布结果和去重状态。
```

此文本只是任务示例，不会自动建立计划。[官方定时任务说明](https://learn.chatgpt.com/docs/automations?surface=app)支持在任务中调用 skill；本地任务需要电脑开机、宿主运行，并能访问所需本地文件。实际浏览器登录、后台权限和工具可用性需要在自己的环境验证。会话失效时停止发送并通知，不承诺永不中断。

## 私有数据放在哪里

请在**公开仓库之外**建立私有目录，保存目标账号、回复账号、授权范围、时区、回复上限、原帖、来源审阅、截图、发布记录和运行报告。

推荐一个状态文件和一个报告目录即可。去重键为平台、原帖 ID 和回复账号 ID 的组合。提交前先写 `submitting`，确认后写 `published`；结果不明保留 `uncertain`，不自动盲重试。具体格式见 [operations.md](skills/sharp-sidekick/references/operations.md)。

Git 忽略规则只是辅助，不是防泄漏保证。发布前检查暂存内容与提交作者信息；不要将真实案例、账号 ID、浏览器凭证、本地用户名或截图复制进公开仓库。

## 验证与贡献

本项目是 instruction-only skill，无运行时依赖和独立测试服务。使用宿主的 skill validator 检查清单格式；再用 [calibration.md](skills/sharp-sidekick/references/calibration.md) 中的场景检验决策质量。格式检查通过不等于回复一定准确，也不等于后台调度和社交发布已经在所有环境通过测试。

欢迎改进筛选标准、来源核对及执行可靠性。提交例子请使用虚构或取得许可并充分去标识化的内容；不要附带私人运行日志或账号配置。
