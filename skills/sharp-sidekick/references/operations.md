# 发布与周期运行

本文件在发布或定期复查时读取。所有账号配置、原帖数据、截图和运行记录保存在公开仓库之外。

## 私有配置

宿主任务至少提供：

- 目标主页或稳定账号 ID；回复账号的稳定 ID 与显示名。
- 时间范围、时区、每轮回复上限，以及发布授权的范围。
- 可用的已登录浏览器或连接器。
- 私有状态文件和运行报告目录。

用户名和 Cookie 不写进 skill；不导出登录凭证。不要把安装 skill 等同于允许其发言。

## 每轮工作

1. **防止并发**：宿主不保证串行时，对该目标使用私有运行锁。发现有效锁则退出；不盲删状态不明的锁。
2. **确定窗口**：以实际运行开始时间为上界，往前取指定天数，使用半开区间 `[start, end)`。记录时区及带偏移量的时间。延迟运行不默认补发整个积压时期；漏跑补查由用户决定。
3. **读取状态**：查看已发布、提交中、结果不明及人工否决的记录，再收集窗口内的帖子。已发布或用户否决的原帖默认不再回复。
4. **完整筛选**：按时间翻页至窗口下界，防止只看第一屏。排除置顶旧文和窗口外内容。无法覆盖窗口时记录缺口；不能宣称“本周无值得回复”。对已完整核实的候选可在授权范围内处理，未读部分不推测。
5. **核对身份**：打开当前登录账号主页核对稳定 ID。账号不对或会话失效时停止发送并报告，不用另一个账号代发，不更改关注列表。
6. **重新检查**：发送前重读原帖及评论，确认作者未更正、内容未变化、回复未重复，并确认草稿仍成立。
7. **写入待提交记录**：在点击发送前持久化 `submitting`，包含原帖 ID、回复账号 ID、准确回复文字及时间。
8. **发送一次**：只有当前任务明确授权时发送。在评论区验证账号与完整正文；能获得评论链接则保存，否则保存原帖链接及可用截图。
9. **写入结果**：确认成功写 `published`；明确失败写 `failed`；超时、工具中断或状态不明写 `uncertain`，停止该条自动重试。

### 不重复发送

以 `platform + target_post_id + reply_account_id` 为去重键。结果不明时先回读评论：找到相同账号和文字就补记成功；不能确定则交给人工处理，不因为本地没有成功标记就重发。提交中记录在后续运行按结果不明处理。

这是降低重复风险的工作流，不是事务性 exactly-once 保证。文件状态与第三方评论系统不能原子提交；断网、审核延迟及评论折叠都可能要求人工核对。

## 最小状态结构

不要求数据库。一个私有 JSON 文件即可；更新时写临时文件并原子替换。每个 record 示例：

```json
{
  "platform": "example-social",
  "target_post_id": "example-post",
  "reply_account_id": "example-bot",
  "post_url": "https://example.com/posts/example-post",
  "reply": "待发送的准确文字",
  "status": "submitting",
  "attempted_at": "2026-01-01T10:00:00+00:00",
  "published_at": null,
  "evidence_path": null
}
```

状态取值：`draft`、`rejected`、`skipped`、`submitting`、`published`、`failed`、`uncertain`。记录人工否决原因；一般跳过原因可以放在当轮 Markdown，不必无限扩充状态文件。

## 运行报告

私有报告记录窗口、读取覆盖、候选及取舍、来源、准确回复文字和发送结果。无候选也记录完成状态，但不为凑汇报打扰用户。有发布就给出链接；登录失效、工具缺失或无法核验结果时说明具体阻碍。

调度由宿主实现。浏览器会话是否保留、电脑是否需要开机、权限是否支持后台执行，都依赖环境；skill 不能承诺无人值守一定成功。遇到登录或验证码需求时交还用户，不绕过验证。
